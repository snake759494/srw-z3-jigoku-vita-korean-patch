# 통합 한글 패치 실행

공개 저장소에는 게임 파일 자체가 아니라 자기 소유 원본에 적용할 델타와 대사 JSON만 들어 있습니다. `scripts/apply_release_patch.py`가 본편·DLC의 모든 항목을 먼저 해시 검증한 뒤 별도 출력 폴더를 만듭니다.

## 적용 범위

현재 `config/release-patch.json`의 Vita3K 릴리스는 253개 항목입니다.

| 영역 | 항목 | 적용 방식 |
|---|---:|---|
| 시나리오 대사 | 182개 (본편 153, DLC 29) | STG/DLC CPK xdelta |
| 전투 대사 | 1개 | `SRVC.BIN` 원문-번역 쌍 JSON + 고정 슬롯 검증 |
| 사전 대사 | 1개 | `MtZkn_KW.cpk` 일본어-한국어 JSON + `0x5E` XOR·가변 길이 CPK 리팩 |
| 메뉴·기체명 등 | 3개 | `rpw_data.cpk`, `AIDDataPack.cpk`, `KDataVITA.cpk` xdelta |
| 실행 파일·맵·시스템 | 66개 | `eboot.bin`, `map_001~064.zld`, `param.sfo` xdelta |

따라서 xdelta는 본편 222개와 DLC 29개이고, 전투 대사 JSON과 `MtZkn_KW` 사전 JSON
실행기가 각각 한 개씩입니다. `MtZkn_Pt/Rt`와 일부 `eboot` 재번역 자료는
`translations/retranslation-extra/`에 검수용 초안으로만 보관되어 있으며, 적용
완료된 릴리스 항목으로 가장하지 않습니다. 사전의 추출·번역·리팩 세부 절차는
[사전 대사 추출과 패치](사전_대사_추출과패치.md)를 참고하세요.

## 한 번에 적용하기

저장소 루트에서 PowerShell을 열고 다음을 실행합니다.

```powershell
# 1) 잠금된 공식 xdelta3 ZIP을 내려받아 해시를 확인합니다.
python scripts/prepare_xdelta3.py --output private/tools/xdelta3.exe

# 2) 본편과 DLC를 별도 트리에 생성합니다.
python scripts/apply_release_patch.py `
  --game-root 'C:\내_덤프\PCSG00264' `
  --dlc-root 'C:\내_덤프\addcont\PCSG00264' `
  --xdelta 'private\tools\xdelta3.exe'
```

`--game-root`는 `eboot.bin`, `DATA`, `CommonData`, `sce_sys`가 바로 들어 있는 본편 폴더여야 합니다. `--dlc-root`는 `SRWZ3OF1DLC00301` 같은 폴더가 바로 들어 있는 DLC 폴더입니다. DLC가 없으면 `--dlc-root`를 생략하고 `--include main`을 지정합니다.

실행기가 출력하는 경로(예: `output/release-candidate/vita3k/20250723T...Z`) 아래에는 다음처럼 분리된 결과가 생깁니다.

```text
app/                         본편 PCSG00264에 넣을 파일 트리
addcont/                     DLC 트리
release-report.json          입력·도구·출력 SHA-256 및 항목별 결과
app/DATA/BTLC/SRVC.BIN.report.json
```

이 결과를 Vita3K의 별도 테스트 인스턴스에 수동으로 연결해 확인합니다. 실행기는 게임 설치 폴더를 찾거나 덮어쓰지 않으며, 원본 입력 파일도 수정하지 않습니다.

## 검증과 범위 선택

기본 범위는 `all`입니다. 필요하면 아래처럼 본편 또는 DLC만 만들 수 있습니다.

```powershell
python scripts/apply_release_patch.py --game-root 'C:\내_덤프\PCSG00264' `
  --xdelta 'private\tools\xdelta3.exe' --include main

python scripts/apply_release_patch.py --game-root 'C:\내_덤프\PCSG00264' `
  --dlc-root 'C:\내_덤프\addcont\PCSG00264' `
  --xdelta 'private\tools\xdelta3.exe' --include dlc
```

다음 검사를 모두 통과해야 파일이 결과로 남습니다.

1. 매니페스트가 `PCSG00264`, `deltaOnly`, 자기 소유 게임 정책인지 확인합니다.
2. 공식 xdelta3 3.2.0 압축 파일과 실행 파일의 SHA-256을 `config/tools.lock.json`과 비교합니다.
3. 모든 원본 파일의 크기·SHA-256과 델타 파일의 크기·SHA-256을 적용 전에 확인합니다.
4. CPK·실행 파일·맵·메뉴 데이터는 xdelta 해독 뒤 목표 SHA-256을 비교합니다.
5. `SRVC.BIN`은 JSON의 일본어 원문, 한국어 번역, 슬롯 범위, 원문 payload SHA-256, 최종 SHA-256을 전용 실행기로 다시 검사합니다.

해시가 하나라도 다르면 다른 게임 버전이나 이미 수정된 파일로 보고 즉시 중단합니다. 기존 출력 폴더를 의도적으로 교체할 때만 `--overwrite`를 추가합니다.

## CPK를 다시 빌드하는 경우

이 릴리스 실행기는 검증된 CPK 델타를 적용하므로 사용자의 PC에 CRI `cpkmakec.exe`가 없어도 됩니다. 번역을 수정해 새 델타를 만들 때는 [대사 CPK 자동화](대사_CPK_자동화.md)의 추출 → `dialogue-manifest.json` → 명시적 ID 리팩 → 재추출 검증 단계를 사용합니다. `cpkmakec.exe`는 사용자가 공식·허가된 경로에서 준비하는 개인 도구이며 저장소에 넣지 않습니다.

## 보안·저작권

- 본인이 소유하고 합법적으로 덤프한 게임에만 사용합니다.
- 저장소에는 원본/완성 게임 파일, 실행 파일, 비밀키, 계정 자격 증명을 커밋하지 않습니다.
- `patches/release/vita3k/`의 파일은 원본과 완성본을 포함하지 않는 xdelta 델타입니다.
- 출처가 불명확한 기존 `xdelta.exe`나 배치 파일을 실행하지 않습니다. 준비 스크립트가 공식 URL과 고정 SHA-256을 확인합니다.
- 실기 Vita용 eboot 서명·패키지 생성은 아직 공개 실행 범위가 아니며 `--profile vita`로 명시적으로 차단됩니다.
