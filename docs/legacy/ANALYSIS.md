# 원본 아카이브 분석 보고서

기준일: 2026-07-22  
분석 대상: `PCSG00264` 로컬 작업 아카이브(읽기 전용)

## 요약

대상 폴더는 게임 원본만 담은 덤프가 아니라 추출, 번역, 재삽입, 폰트/텍스처 제작, Vita3K 배포, DLC와 실기 실험까지 포함한 기존 한글화 작업 전체입니다. 따라서 새 번역을 처음부터 시작하는 것보다 기존 결과물을 불변 스냅숏으로 보존하고, 중복 스크립트와 여러 문자표를 하나의 재현 가능한 파이프라인으로 정리하는 것이 우선입니다.

## 기존 배포 구조

### 본편

`!배포/PCSG00264_Korean_Create_250102.bat`에는 다음 222개 xdelta 생성 명령이 있습니다.

| 분류 | 개수 |
|---|---:|
| `eboot.bin`, `rpw_data.cpk`, `AIDDataPack.cpk`, `SRVC.BIN` | 4 |
| `DATA/mapetc/attr/map_*.zld` | 64 |
| `DATA/STAGE/STG*.cpk` | 153 |
| `sce_sys/param.sfo` | 1 |

`!배포/Patch/1_README.txt`의 패치 버전은 2025-01-03이며, 게임 버전 1.02와 Vita3K 전용임을 명시합니다. 메뉴/로봇/파일럿/무기와 60화·에필로그까지의 스테이지 대사가 완료되었다고 기록되어 있습니다. 전투 대사는 임시 번역, 사전 데이터와 DLC는 0%라고 쓰여 있습니다.

원본과 `Korean` 트리를 SHA-256으로 비교하면 실제 변경 파일은 219개입니다. 이 중 218개만 xdelta 목록에 있고, 수정된 `DATA/kurodata/KDataVITA.cpk`가 빠져 있습니다. 반대로 `STG0400`, `STG0401`, `STG0904`, `STG0905`는 원본과 한글화 파일 해시가 같은데도 패치 목록에 들어 있습니다.

### DLC와 실기 실험

별도 `!배포-DLC` 문서의 버전은 2025-01-10이며 29개 DLC CPK를 대상으로 하고 “DLC 전체 100% 완료”라고 기록합니다. 본편 README의 DLC 0%와 시점이 달라 통합 문서가 갱신되지 않은 상태입니다.

`!배포-실기`와 `1_eboot_bin (4025)/실기`에는 app/patch용 eboot, ELF 변환 및 주입 실험 흔적이 있으나 독립된 배포 README와 재현 스크립트가 부족합니다. 본편 배포 문서의 “Vita3K 전용”과 분리해 실기용 트랙을 별도 관리해야 합니다.

공식 xdelta 3.2.0으로 251개 델타를 실제 디코딩한 결과 250개는 당시 한글화 파일의 SHA-256과 일치했습니다. 본편 `eboot.bin` 한 개만 불일치했으며, 현재 한글화 eboot가 기존 델타보다 93.4시간 뒤에 수정된 것이 원인으로 보입니다. 이 문장은 2026-07-22 조사 시점의 기록이며, 이후 `patches/release/vita3k/main/eboot_bin.xdelta`를 최신 적용 결과 기준으로 다시 생성해 통합 매니페스트에서 251개 모두 검증했습니다.

## 데이터와 문자 처리

- 스테이지/메뉴/전투/사전 데이터는 CPK 안의 ID 파일을 추출한 뒤 Python 스크립트와 XLSX를 거쳐 재삽입하는 형태입니다.
- 기존 스크립트는 CP932/Shift-JIS, UTF-8 3바이트 문자표, 사용자 정의 TBL을 함께 사용합니다.
- `UTF8_J3B-jk.tbl`은 일본어 영역 뒤에 완성형 한글 음절을 포함한 18,358행 규모의 표입니다.
- 기존 스크립트 885개 중 고유 내용은 65개뿐이므로 각 스테이지 폴더에 복사된 스크립트를 공용 모듈과 데이터 설정으로 통합할 수 있습니다.
- TBL도 237개 중 16개 고유 버전이므로 “어떤 대상 파일이 어떤 문자표를 쓰는지”를 매니페스트로 고정해야 합니다.
- `STG0019(12화B)` 작업 폴더는 `repack` 대신 `reapack`으로 오타가 나 있어 자동 탐색에서 빠질 수 있습니다.
- `STG0202.cpk`는 내부 ID 순서와 작업 폴더의 재패킹 파일명이 뒤바뀐 정황이 확인되어 재패킹과 플레이 검증이 필요합니다.

CPK는 숫자 ID 기반 ITOC와 16바이트 정렬을 사용합니다. 원본 payload는 대체로 CRILAYLA 압축이지만 수정 CPK는 다수가 비압축으로 재생성되어 크기가 증가했습니다. 원본 생산자 메타데이터는 `CPKMC2.42.00 / DLL3.12.00`, 수정본은 `CPKMG2.40.13 / DLL3.24.00`으로 다르지만 해당 CPK 생성기와 자동 빌드 절차는 아카이브에 없습니다. 현재 재현성의 가장 큰 공백입니다.

`eboot.bin`과 일부 BIN 삽입기는 포맷 전체를 재구성하기보다 고정 오프셋 문자열을 바꾸며, 공간을 넘는 번역은 건너뛰는 방식입니다. map ZLD 64개도 고정 길이를 유지합니다. 새 QA는 문자 수가 아니라 실제 인코딩 바이트 길이를 검사해야 합니다.

스테이지 XLSX 265개에는 실제 원문 156,565행이 있고 번역/치환 값은 모두 채워져 있습니다. DLC XLSX 77개도 실제 원문 14,181행의 번역/치환 값이 모두 채워져 있습니다. 그러나 스테이지 6,010행과 DLC 642행은 원문과 번역이 동일하고, 통합 사전의 `검수` 열에는 표식이 없어 수동 품질검수 완료로 해석할 수 없습니다.

`0_STAGE`와 `01_스테이지 xlsx 모음`의 동명 XLSX 265개는 셀 값/수식이 같습니다. 242개는 파일 해시까지 같고 23개는 패키지 바이트만 다릅니다. 새 프로젝트에서는 `01_스테이지 xlsx 모음`을 번역 셀 검수 기준본으로 선언하되, 평탄화 과정에서 빠진 asset provenance는 `0_STAGE` 문맥과 별도 매니페스트로 보존해야 합니다.

## 폰트와 텍스처

- Vita3K 배포용 핵심 폰트 텍스처 두 개는 각각 8192×2240 RGBA PNG이며 파일명은 텍스처 해시 형태입니다.
- 폰트 아틀라스는 일본어 글리프 영역과 한글 글리프 영역을 한 장에 배치합니다.
- 텍스처 작업 폴더에는 2048² 등 고해상도 교체 이미지와 작업 ZIP/PSD가 함께 있습니다.
- 나눔 계열을 포함한 다수 TTF/OTF/PSD가 있으므로 최종 배포에 사용한 정확한 폰트와 라이선스만 남기는 감사가 필요합니다.
- 2025-02-06에 갱신된 내장 폰트용 `ID00001`/`ID00003` 작업물은 기존 `TPACKVITA.cpk`보다 새롭고 TPACK xdelta도 없습니다. 현재 아카이브에서는 이 최신 작업물이 배포 빌드에 통합됐다는 증거를 찾지 못했습니다.
- 최종 텍스처 후보 PNG는 230개지만 고유 해시는 225개로, 완전 중복 5쌍이 남아 있습니다. 작업본과 최종본의 공통 이름 218개 중 185개는 파일 바이트가 달라 PNG→GXT/CPK 대응 매니페스트가 필요합니다.

## 기존 자동화의 위험

기존 적용 BAT는 원본 222개 파일을 먼저 `.bak`으로 바꾸고 xdelta를 순차 적용합니다. 명령별 종료 코드, 입력 해시, 출력 해시를 확인하지 않으며 마지막에는 xdelta와 도구 EXE를 삭제합니다. 중간 실패 시 설치 폴더가 반쯤 변경될 수 있습니다.

새 파이프라인의 필수 조건은 다음과 같습니다.

1. 입력 SHA-256 사전검증
2. 설치 폴더와 분리된 스테이징 출력
3. 각 결과의 SHA-256 사후검증
4. 모든 항목이 성공한 뒤에만 배포용 오버레이 생성
5. 실패 시 원본 무변경과 명확한 오류 보고

## 보안 발견사항

루트의 `gen-lang-client-*.json`은 서비스 계정의 비공개 키 필드를 가진 자격 증명 파일입니다. `trans-test.py`와 `g.py`에도 API 비밀값으로 보이는 평문 리터럴이 있습니다. 값은 보고서나 새 프로젝트에 복사하지 않았습니다. 저장소에 절대 포함하지 말고 공급자 콘솔에서 모두 폐기·재발급해야 합니다.

기존 폴더의 EXE 22개는 모두 Windows 서명 검사에서 `NotSigned`였습니다. 출처가 불명확한 `_decrypt.exe`, CPK/GXT 변환기, 기존 xdelta 실행 파일을 자동으로 실행해서는 안 됩니다.

기존 배포의 `xdelta.exe`는 3.1.0으로 식별됩니다. 새 검증에는 공식 3.2.0 Windows 릴리스와 고정 SHA-256을 사용했습니다. `psp2gxt.exe`에는 독점 SDK/기밀성 문구가 있어 재배포 대상에서 제외하고 라이선스가 명확한 대체 경로를 찾아야 합니다.

## 결론

번역 결과 자체는 본편 시나리오와 DLC까지 상당히 진행됐습니다. 프로젝트의 다음 병목은 번역량보다 재현성, 소스 정규화, 품질검사, 폰트/도구 출처, 실기판 분리입니다. `manifests/legacy-*.json`은 기존 결과를 잃지 않고 새 파이프라인으로 옮기기 위한 기준점입니다.
