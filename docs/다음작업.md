# 다음 작업

새 프로젝트는 현재 “자료 이관과 안전 기반 완성” 단계입니다. 아래 순서대로 진행하면 한 번에 너무 많은 코드를 건드리지 않고 기존 결과를 재현할 수 있습니다.

## 1. 신규 대사 번역 계속

- `STG0001a` 93행은 일본어 원문 기준 신규 번역과 독립 교차검수, 원문 결박 검사를 완료했습니다.
- `STG0001b` 558행은 일본어 원문 기준 신규 번역과 구조 검사를 완료했으며 2차 문맥 검수 대기 중입니다.
- 다음 번역 대상은 `STG0002` 1,443행입니다.
- 기존 번역은 로컬 작업 JSON의 `references`에서만 확인하고 새 번역으로 자동 복사하지 않습니다.
- 자산 하나를 마칠 때마다 `translations/retranslation/progress.json`을 갱신합니다.
- 새 번역은 먼저 `draft`로 두고, 문맥·고유명사·행 연결을 다시 읽은 뒤 `reviewed`로 올립니다.

## 2. 기존 검수 대상 393행 확인

- `work/normalized/translations.tsv`에서 상태가 `blocked`인 행만 별도 검수표로 내보내는 도구를 만듭니다.
- 제어 토큰 불일치 125행과 기록된 바이트 길이 초과 268행을 구분해 보여 줍니다.
- 원문, 최종 번역, 한글폰트 치환문 사이의 제어 토큰 개수와 순서를 사람이 확인합니다.
- 확인 전에는 `approved`로 바꾸지 않습니다.

## 3. 원본 프로필 확정

- 실제 본편·DLC 덤프 경로를 로컬 설정에 연결합니다.
- eboot, STAGE, DLC, AID, rpw, SRVC, KData 파일마다 원본 SHA-256을 기록합니다.
- 일반 문자표와 `(oper)` 문자표, WReplace 파일의 SHA-256도 함께 고정합니다.

주소값만 맞는 다른 버전 파일에는 절대 삽입하지 않습니다.

## 4. 대표 스테이지 라운드트립 — 완료

- 대표 `STG0001a`의 무수정 대사 재조립이 원본 payload와 바이트 단위로 일치했습니다.
- 실제 XLSX 반영 결과의 ID3/ID4가 기존 `zID00004`와 바이트 단위로 일치했습니다.
- CPK를 명시적 ID로 리팩한 뒤 전체 8개 ID를 다시 추출해 해시를 검증했습니다.
- 같은 입력을 두 번 빌드한 CPK SHA-256도 일치했습니다.
- `DLC0301`의 ID3/ID4와 승인된 제어 토큰 변경 3행도 전체 과정을 통과했습니다.

## 5. 기존 빌드 재현

- `MtZkn_KW` 사전 대사는 141개 멤버·564개 태그 추출, 신규 번역 JSON, XOR·ITOC
  가변 길이 리팩과 결과 재검증까지 구현했습니다. 남은 일은 실제 Vita3K 화면에서
  긴 설명의 줄바꿈·폰트 표시를 사람이 확인하는 것입니다.

1. 일반 STAGE와 DLC 스크립트 — 대표 실파일 구현·검증 완료, 전체 일괄 검증 필요
2. `ID00001`의 `OPERATE_TBL`과 팀명
3. eboot UTF-8 영역
4. eboot Shift-JIS 영역
5. AIDDataPack, rpw_data, SRVC, KData

각 자산은 기존 결과와 새 결과의 SHA-256 차이를 설명할 수 있을 때만 완료로 봅니다.

## 6. 패키징과 배포 검사

- 대사 CPK는 로컬 `cpkmakec.exe` SHA-256, 명시적 ID CSV, ID 모드, 16바이트 정렬, 무압축 옵션을 고정했습니다.
- 대사 외 CPK 자산과 GXT의 도구·옵션은 별도로 확정합니다.
- 항상 `work/staging`에서 만들고 원본 폴더에는 쓰지 않습니다.
- xdelta 생성 후 깨끗한 원본에 역적용해 최종 SHA-256을 확인합니다.
- Vita3K 검증과 실제 PS Vita 검증 결과를 분리해 기록합니다.
- 폰트와 텍스처의 재배포 권리가 확인된 자료만 릴리스 후보에 넣습니다.
