# 번역 데이터 규칙

## 기준 열

- `source_text`: 변경하지 않은 일본어 원문
- `translation`: 사람이 읽고 고칠 최종 한국어. 기존 XLSX에서는 `제미니번역`을 우선 가져옵니다.
- `replacement_text`: 게임 문자표로 치환된 삽입 문자열
- `google_translation`, `legacy_translation`: 참고용이며 최종 번역으로 자동 승인하지 않습니다.
- `source_artifact_sha256`: 가져온 XLSX 전체 파일의 SHA-256
- `payload_sha256`: 실제 원본 바이너리 payload와 연결한 뒤 기록

## 행 ID

`STG0002/ID00003/000004`처럼 `자산/내부ID/원본행번호`로 만듭니다. 파일명과 시트명이 다르면 어느 쪽도 버리지 않고 `ID00003@FILE-ID00004`처럼 함께 기록하고 보고서에 경고합니다. 분기 원고는 분기명을, 같은 이름을 쓰는 DLC 원고는 상위 DLC 번호를 ID에 포함해 중복을 막습니다.

## 제어 토큰

`⑲`, `⑳`, `㊥`, `㊦`, `㊧`, `㊨`, `$n`, `$l`, `$c` 등의 순서와 개수를 보존합니다. 치환문에서 전각 영문으로 바뀐 `$ｎ` 등은 비교할 때 같은 토큰으로 정규화합니다.

## 상태

- `imported`: 기존 원고에서 자동으로 가져온 상태
- `review`: 사람이 검수 중
- `approved`: 번역·제어 토큰·문자표·실제 바이트 길이·payload 해시가 모두 확인됨
- `blocked`: 입력 누락이나 구조 오류

가져오기만으로 `approved`가 되지 않습니다.
