# 빌드와 검사

## 새 공용 코드가 보장해야 하는 것

1. 원본 SHA-256이 프로필과 일치할 것
2. 주소가 파일 범위 안이고 서로 겹치지 않을 것
3. 원본 바이트가 기대값과 일치할 것
4. 모든 문자가 선택 문자표에 있을 것
5. 인코딩 결과가 허용 길이를 넘지 않을 것
6. 오류가 있으면 출력 파일을 게시하지 않을 것
7. 결과는 원본 밖의 새 스테이징에만 만들 것

## 단계별 목표

1. 기존 XLSX를 정규 TSV로 한 번만 이관
2. 합성 데이터로 TBL과 고정 길이 패치 테스트
3. 대표 STAGE 한 개를 추출→무수정 재조립해 바이트 동일성 확인 — 완료
4. eboot UTF-8→Shift-JIS 두 단계 빌드 재현
5. 대사 CPK 생성기와 옵션 확정 — 완료, 다른 CPK 자산은 미완료
6. xdelta 생성 후 역적용 결과 해시 확인
7. Vita3K와 실기 Vita를 별도 테스트

기존 BAT의 원본 이름 변경·직접 덮어쓰기·백업 삭제 방식은 사용하지 않습니다.

대사 CPK의 구현된 검사 순서는 [대사 CPK 자동화](대사_CPK_자동화.md)를 참고하세요.

## 통합 릴리스 패치 검사

세 영역과 부속 파일을 적용하는 공개 경로는 `scripts/apply_release_patch.py`입니다.
`config/release-patch.json`에 원본·적용 결과·델타의 SHA-256이 모두 기록되어 있고,
본편 222개 xdelta, DLC 29개 xdelta, `SRVC.BIN` JSON 1개를 처리합니다.

```powershell
python scripts/prepare_xdelta3.py --output private/tools/xdelta3.exe
python scripts/apply_release_patch.py `
  --game-root 'C:\내_덤프\PCSG00264' `
  --dlc-root 'C:\내_덤프\addcont\PCSG00264' `
  --xdelta 'private\tools\xdelta3.exe'
```

실행 전 모든 입력을 해시 검사하고, 실행 후 모든 출력도 매니페스트의 목표 해시와
비교합니다. 결과는 `output/release-candidate/` 아래의 별도 `app`·`addcont` 트리와
`release-report.json`에만 기록합니다. `--profile vita`는 실기 서명 절차가 확정되지
않았으므로 실패하도록 되어 있습니다.
