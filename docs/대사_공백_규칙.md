# 대사 공백 규칙

사람이 확인·수정하는 번역 JSON의 일반 공백은 ASCII 반각 공백(`U+0020`)으로 통일한다.
게임에 넣는 최종 바이트에서는 이 반각 공백을 반드시 `FE FE`로 치환한다.
전각 공백(`U+3000`)은 일본어 원문, 원문 매칭용 데이터, CPK 스크립트의 구조용 접두부에서만 보존한다.

## 정규화 대상

- `translations/dialogue/**/*.json`의 `translation`
- `translations/battle-dialogue/**/*.json`의 `translation`
- `translations/dictionary/**/*.json`의 `translation`
- 시나리오 뷰어에서 불러오거나 편집·저장·CPK 빌드하는 번역 문자열
- Python CPK 재조립 경로(`stage_script`, `scenario_cpk`)
- 사전 고정 슬롯 인코더(`translate_dictionary.py`)

원문 `sourceText`, `replacementText`, `sourcePayload`, `appliedPayload`는 원본 매칭과 바이트 검증에 사용되므로 자동으로 바꾸지 않는다. 같은 객체의 `translationTextSha256`가 있으면 정규화 후 UTF-8 SHA-256으로 갱신한다.

## 반복 실행

저장소 루트에서 다음 명령을 실행하면 공개 JSON을 정규화한다.

```cmd
python scripts\normalize_dialogue_spaces.py
```

변경 예정만 확인하려면 다음과 같이 실행한다.

```cmd
python scripts\normalize_dialogue_spaces.py --check
```

이 규칙은 전각 공백을 포함한 번역을 새로 입력해도 CPK 빌드 직전에 다시 적용한다. 따라서 뷰어에서 저장하지 않고 바로 `현재 시나리오 CPK 빌드`를 눌러도 JSON에는 반각 공백이 남고, CPK payload에는 `FE FE`가 기록된다.

CP932에서 `U+F8F2`는 단일 바이트 `FE`로 인코딩되므로, 코드에서는 반각 공백 하나를 `U+F8F2 U+F8F2`라는 내부 게임 글리프로 바꾼 뒤 인코딩한다. CPK 구조용 전각 공백은 기존처럼 `81 40`으로 보존한다.
