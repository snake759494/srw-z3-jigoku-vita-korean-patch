# 스테이지 승리·패배·SR 조건

## 저장 위치와 형식

스테이지 조건은 대사 JSON과 섞지 않고 `translations/conditions/scenario_<asset>.json`에 저장합니다. 각 항목에는 다음 정보가 함께 들어갑니다.

- `sourceText`: 원본 CPK `ID00001`의 일본어 원문
- `translation`: 게임에 넣을 한국어
- `conditionTypes`: `win`(승리), `defeat`(패배), `sr`(SR 포인트), `other`
- `sourceId`: `OPERATE_TBL.str_tbl`의 ID

따라서 번역자는 일본어·한국어 쌍을 직접 확인하고 JSON의 `translation`만 수정할 수 있습니다. 원본 게임 파일과 CPK는 저장소에 포함하지 않으며, 본인 소유의 게임 덤프를 로컬에서 사용합니다.

## 원본 구조

조건은 시나리오 대사 파일이 아니라 각 스테이지 CPK의 `ID00001` 안에 있는 다음 테이블에 있습니다.

```lua
OPERATE_TBL = {
  str_tbl = {
    -- ID : 0
    "敵の全滅。",
  };
  id_tbl = {
    0,-1,-1, -- 勝利条件
  };
}
```

`id_tbl`의 주석을 분석해 조건 종류를 붙이고, `str_tbl`의 ID를 기준으로 원문과 번역을 연결합니다. 문자열 교체 범위는 `OPERATE_TBL.str_tbl`뿐이므로 적 편성·맵 데이터 등 다른 스테이지 설정은 변경하지 않습니다.

## 빌드

일반적인 전체 빌드는 저장소 루트에서 다음처럼 실행합니다.

```cmd
set PYTHONPATH=src
python scripts\build_all_scenario_cpks.py
```

`build_all_scenario_cpks.py`가 대사 JSON과 같은 asset의 조건 JSON을 자동으로 합쳐 CPK를 만들고, 추출·리팩 후 모든 payload 해시를 다시 검사합니다. 조건이 적용된 결과에는 빌드 보고서의 `conditionEntries`, `patchedConditionEntries`, `unmatchedConditionEntries`가 기록됩니다. `unmatchedConditionEntries`가 0인지 확인한 뒤 Vita3K의 `ux0\app\PCSG00264\DATA\STAGE`에 복사된 파일을 사용합니다.

조건 문자열은 게임의 기존 `Japanese - Hangul to Kanji(oper).wReplace` 방식(전각 공백 포함)을 그대로 사용합니다. 일반 시나리오 대사의 반각 공백 `0xFEFE` 규칙과는 저장 포맷이 다르므로, 조건 JSON에는 일반 공백을 입력하고 빌드기가 operation 치환표를 적용합니다.

## 조건 JSON 재생성

원본과 기존 개인용 한글 CPK에서 조건 JSON을 새로 추출해야 할 때만 다음 명령을 사용합니다.

```cmd
set PYTHONPATH=src
python scripts\extract_stage_conditions.py
```

이 명령은 게임 파일을 저장소에 복사하지 않습니다. 기존 한글 CPK가 있으면 operation 치환표를 역변환해 현재 번역을 채우고, 없으면 `translationStatus`를 `untranslated`로 표시합니다. 특정 스테이지만 추출하려면 `--only STG0001b`를 붙입니다.
