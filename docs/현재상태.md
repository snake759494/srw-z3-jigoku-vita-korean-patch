# 현재 상태

- 기존 아카이브: 14,425개 파일, 약 8.00GiB
- Python: 885개 파일이지만 고유 내용은 65개
- 본편 스테이지 원고: 265개 XLSX, 실제 원문 156,565행
- DLC 원고: 77개 XLSX, 실제 원문 14,181행
- 사전 원고: 1개 XLSX, 실제 원문 4,464행
- 정규화 결과: XLSX 343개 전부 인식, 총 175,210행, 고유 ID 175,210개
- 이관 상태: `imported` 174,817행, `blocked` 393행
- 레거시 패치: 본편 222개, DLC 29개 xdelta
- 공개 릴리스 델타: 본편 222개(시나리오·메뉴·기체명·eboot·맵·시스템), DLC 29개
- 공식 xdelta3 3.2.0으로 251개 델타 역적용 결과가 기존 적용 결과 SHA-256과 일치
- 통합 실행 매니페스트: 253개 항목(델타 251개 + SRVC JSON 1개 + MtZkn_KW 사전 JSON 1개)
- MtZkn_KW 사전 대사: CPK 141개 멤버·564개 태그를 0x5E XOR 해제해 추출했고,
  일본어 원문-한국어 번역 JSON과 가변 길이 CPK 리팩 실행기를 연결함
- MtZkn_KW 번역 상태: 564개 모두 번역 초안 생성(`draft` 280개,
  `overflow-repacked` 284개), 자동 번역 품질은 화면 검수 필요
- 대사 CPK: 추출→XLSX 대조→정규 JSON 생성·재로딩→CP932 재조립→명시적 ID 리팩→재추출 해시 검증 구현
- 대표 실파일: `STG0001a`와 `DLC0301`의 XLSX 빌드 및 생성 JSON 직접 재빌드가 같은 CPK SHA-256으로 통과
- 자동 테스트: `python -m unittest discover -s tests -v` 88개 통과

기존 Python의 핵심 문제는 미등록 문자 삭제, 길이 초과 후 계속 실행, 원본 해시 미검사, 주소 겹침 미검사와 중복 코드입니다. 특히 전각 공백에 `b'\x8140'`을 사용한 코드는 실제 `81 34 30` 세 바이트가 되므로 새 코드에서는 금지합니다. 올바른 Shift-JIS 전각 공백은 `81 40`이며, 게임에 삽입하는 반각 공백은 별도 글리프 `FE FE`로 기록합니다.

새 프로젝트는 오류가 하나라도 있으면 결과를 만들지 않는 것을 원칙으로 합니다.

대사 CPK는 파일명·시트명으로 ID를 추론하지 않습니다. 기존 자료에서 확인된 잘못된 시트명과 `STG0202`의 ID3/ID4 순서 문제를 막기 위해 대상 ID와 필요시 원본 ID를 명시합니다. 자세한 내용은 [대사 CPK 자동화](대사_CPK_자동화.md)에 있습니다.

`blocked` 393행은 삭제하거나 임의 수정하지 않았습니다. 이 가운데 125행은 최종 번역과 한글폰트 치환문 사이에서 `⑲`, `$n`, `$l`, `$c` 같은 제어 토큰의 개수나 순서가 다르고, 268행은 사전 XLSX에 기록된 길이가 기존 바이트 한도를 넘습니다. 이 상태는 “이관 실패”가 아니라 “자동 승인 금지”를 뜻합니다.
