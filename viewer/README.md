# 시나리오 대사 HTML 뷰어

`시나리오_대사_뷰어.html`은 저장소에 포함된 시나리오 카탈로그를 읽어 실제 게임풍
대사창으로 대사를 확인하고 현재 화면의 번역을 수정하는 도구입니다. 파일 선택 창을 띄우지 않으며,
목록에서 화·분기를 고르면 해당 JSON 하나만 불러옵니다. 신규 재번역이 끝난
1화(`STG0001a/b`)·2화(`STG0002`)·3화(`STG0003`)·4화(`STG0004`)·5화(`STG0005`)에서는 `sourceText` 일본어 원문,
기존 `translation`, 신규 재번역 `newTranslation`을 1행·2행·3행에 세로로 쌓은
대사창으로 비교합니다. 각 대사창 내부는 버전명·화자명·대사
3열로 정리하며, 기존 번역은 그대로 보존되므로 두 번역을 안전하게 비교할 수 있습니다.

## 사용 방법

1. `시나리오_대사_뷰어_실행.cmd`를 실행합니다. 저장소 루트에서 로컬 웹 서버가 열리고
   브라우저가 뷰어로 이동합니다.
   실행할 때마다 주소에 새 캐시 키가 붙고 HTML·JSON은 `no-store`로 전달되므로,
   이전에 열었던 뷰어 화면이 남지 않습니다. 이미 열린 이전 탭은 닫아도 됩니다.
2. 왼쪽 **시나리오 목록**에서 본편·분기 또는 DLC 시나리오를 바로 선택합니다.
3. 선택한 시나리오의 기존 번역 행에서 한 줄 최대 글자 수를 자동으로 산출합니다.
   각 번역 행을 줄바꿈 단위로 나누고 제어문자는 기본값으로 치환한 글자 수 중
   최댓값을 사용합니다. `metadata.byteLimit`가 있고 ⑲·㊦ 같은 패딩 제어문자가 반복되는
   고정 슬롯 행은 일반 대사창의 기준에서 제외합니다. 이 값은 `최대 N/기존 최대`
   배지와 초과 줄 표시의 기준입니다. 세 대사창에는 이 기준에 맞춘 원고지 격자가
   표시되어 한 칸 경계를 바로 확인할 수 있습니다.
4. 검색어·검수 상태·원문 표시를 조절하고 `←/→`, `↑/↓`, `Home`, `End`, `Space`로
   한 화면씩 대사를 이동합니다.
5. 왼쪽 **현재 시나리오 CPK 빌드**를 누르면 현재 화면에서 수정한 메모리상의 JSON까지
   포함해 원본 CPK를 추출하고, 한글 문자표 치환·대사 조립·명시적 ID 리팩·재추출
   payload 검증을 한 번에 수행합니다. 결과는 `output/dialogue/<시나리오>/<실행ID>/`에
   저장되며 원본 CPK는 덮어쓰지 않습니다. 생성된 결과와 보고서 링크가 버튼 아래에
   표시됩니다.

번역 문자열의 공백은 불러오기·편집·저장 단계에서 전각(`U+3000`)을 반각 일반 공백
(`U+0020`)으로 바꿉니다. CPK 빌드 단계에서는 이 반각 공백을 게임 바이트 `FE FE`로
치환합니다. 공개 JSON 전체를 한 번에 정리하려면 저장소 루트에서
`python scripts\normalize_dialogue_spaces.py`를 실행하세요. 원문과 CPK 구조용 전각
공백은 원문 매칭을 위해 보존합니다.

HTML을 직접 열면 브라우저가 `fetch`를 차단할 수 있습니다. 이 경우 반드시 실행 명령을
사용하거나 저장소 루트에서 다음 명령으로 서버를 띄우세요.

```powershell
python scripts/scenario_viewer_server.py --port 8765
```

그 다음 <http://127.0.0.1:8765/viewer/시나리오_대사_뷰어.html>을 엽니다. 포트를 바꾸려면
실행 전에 `SIOK_VIEWER_PORT` 환경 변수를 지정할 수 있습니다.

CPK 빌드 버튼은 이 실행 명령이 시작한 로컬 서버의 `/__siok__/build-cpk` API를
사용합니다. HTML 파일을 직접 열면 브라우저가 프로세스 실행과 API 요청을 차단하므로
버튼을 누르기 전에 반드시 실행 명령으로 뷰어를 여세요. `private/project.local.json`의
`cpkToolPath`에는 `config/tools.lock.json`의 SHA-256과 일치하는 본인 소유
`cpkmakec.exe` 경로를 지정해야 합니다. 원본 CPK는 `archiveRoot` 또는 저장소와
같은 작업 폴더의 `PCSG00264` 아래에서 자동으로 찾고, 표준 SHA-256의
`Japanese - Hangul to Kanji.wReplace`도 함께 찾습니다. 구조가 다르면 설정에
`wReplacePath`를 추가할 수 있습니다.

실행 명령은 Windows용 CRLF 줄바꿈으로 저장되어 있습니다. Git 설정이나 편집기가
줄바꿈을 LF로 바꾸면 `시작하기.cmd`와 `viewer/시나리오_대사_뷰어_실행.cmd`를
메모장 대신 저장소에서 다시 받아 실행하세요.
뷰어 실행 CMD 자체는 코드페이지 영향을 받지 않도록 ASCII 문자와 UTF-8 퍼센트
인코딩 URL만 사용합니다. 따라서 Windows 기본 ANSI/CP949 환경에서도 파일을
직접 더블클릭해 실행할 수 있습니다.

## 카탈로그 갱신

시나리오 JSON을 추가·삭제한 뒤에는 저장소 루트에서 아래 명령을 실행합니다.

```powershell
python scripts/build_scenario_catalog.py
```

이 명령은 `viewer/scenario-index.json`을 갱신합니다. 카탈로그에는 파일명·시나리오 키·
행 수·상대 경로만 저장하고, 실제 대사는 뷰어가 선택한 순간에 지연 로딩합니다.

화자 행 경계를 처음 만들거나 원본 CPK를 교체한 경우에는, 본인이 소유한 게임에서
추출한 `STAGE/<시나리오>/IDxxxxx` 폴더를 지정해 다음 명령도 실행합니다.

```powershell
python scripts/build_scenario_speaker_catalog.py `
  --source-root "D:\Z\psvita\PCSG00264\0_STAGE"
```

이 명령은 CPK 스크립트의 `SP/SB/SF/SG` 슬롯과 JSON의 `sourceRow`를 대조해
`viewer/scenario-speakers.json`을 만듭니다. 카탈로그에는 원문·번역문을 넣지 않고
`시나리오/내부 ID/sourceRow`와 화자 슬롯 여부만 저장합니다. 뷰어는 이 목록을
우선 사용하므로 `카나메`·`쿄코`·`소스케`·`???`처럼 다음 대사와 길이가 같거나 짧은
화자도 대사 안으로 합치지 않습니다. `ID00003@FILE-ID00004`처럼 `@FILE-` 뒤의
실제 CPK 파일이 바뀌는 지점도 별도 멤버로 끊어 이전 화자를 물려주지 않습니다.

## 화면 구성

- 화자명 행은 다음 대사와 자동으로 묶어 게임풍 이름표로 표시합니다. 오인식할 경우
  **화자명 행 자동 묶기**를 끄면 원본 JSON 행 단위로 볼 수 있습니다.
- 한 화면에는 대사 최대 3행을 표시하고, 실제 게임처럼 첫 행 앞에 `「`, 마지막 행
  뒤에 `」`를 표시합니다. 첫 행의 첫 칸은 `「`, 2행·3행의 첫 칸은 표시용 반각
  공백으로 두며, 빈 행도 화면 슬롯으로 남겨 세 번째 줄을 비워 둡니다. 이 접두
  칸과 합성 괄호는 글자 수에 포함하지 않습니다.
- **일본어 원문 함께 보기**를 켜면 대사창이 1행(일본어 원문)·2행(기존 번역)·
  3행(신규 번역) 순서로 세로 배치됩니다. 각 창 안에서는 버전명·화자명·대사를
  3열로 나란히 확인할 수 있으며, 제어문자만 있는 행은 대사 줄로 세지 않습니다.
  대사 안의 색상 토큰으로도 확인할 수 있습니다.
- 신규 번역은 JSON의 `newTranslation` 필드입니다. 아직 이 필드가 없는 시나리오에서는
  신규 창을 숨기고 나머지 창을 자동으로 넓힙니다. 세 창 모두 게임의 3줄 슬롯에
  맞춘 높이를 사용하므로, 내용이 길어져도 창 자체가 늘어나지 않습니다.
  3줄·괄호·원고지 격자·한 줄 최대치 규칙으로 미리보기 되며, `《용어》` 표시는
  대괄호는 숨기고 본문만 분홍색으로 확인합니다.
- 원고지 격자는 단순한 가로·세로 배경선이 아니라 기존 번역에서 산출한 한 줄
  최대 칸 수만큼 HTML 표의 `td` 문자 칸을 만들고, 각 글자와 반각 띄어쓰기를 한 칸씩 배치합니다.
  반각 띄어쓰기는 문자를 그리지 않고 빈 `space-cell` 한 칸으로 유지하며, 셀 배경과
  마우스 오버 설명으로 공백이 사라진 것이 아님을 확인할 수 있습니다.
  `《용어》`는 괄호를 숨긴 본문을 분홍색으로 글자별 배치하고, `$n`·`$l`·`$F`·`$c` 및
  `&n`·`&l` 같은 제어문자는 `히비키`·`카미시로`·`히비키 카미시로`·`Z-BLUE`로
  펼쳐 각 글자를 실제 원고지 칸에 배치합니다. 창 장식용 긴 가로선은 제거하고, 표의 위·아래·오른쪽
  테두리, 3개 대사 행 사이의 가로 구분선과 문자 칸의 세로 구분선을 표시합니다.
- `『천사』`·`【注意】`처럼 대사 안에 들어간 문장부호는 용어 표기인 `《》`와 다릅니다.
  괄호를 숨기거나 겹치지 않고 `『`·`천`·`사`·`』`처럼 일반 글자와 동일하게 한 칸씩
  배치하며, 줄바꿈·최대 칸 수 검사에도 네 칸으로 반영합니다. 게임 대사창 바깥의
  장식용 `「」`만 표시용 접두·종료 부호로 처리합니다.
- 대화형 대사는 표시 전용 접두 칸을 하나 둡니다. 첫 행의 첫 칸에는 `「`를,
  둘째·셋째 행의 첫 칸에는 반각 공백을 넣고 실제 대사는 두 번째 칸부터 시작합니다.
  두 줄 이상인 대사의 첫 행에만 괄호 뒤 표시용 공백을 추가하며, 한 줄 대사의
  첫 실제 공백은 삭제하지 않습니다. 이 접두 칸은 기존 번역의 글자 수 한도에는
  포함하지 않습니다.
- `나레이션`(`ID00007` 등 pid가 없는 CPK 멤버)은 화자명과 앞뒤 괄호를 표시하지
  않습니다. 지역 행도 별도 화면으로 분리해 `지역 표시`로 보여 주며 괄호를
  붙이지 않습니다. 특히 원본 `STG0001b`의 `ID00003` 191행은 CPK에서
  `pid_MUZIN`·`FDMode_NoDraw_or_FDMode_OnlyBGName`인
  `～陣代高校　校門付近～` 행이므로 앞뒤 대사 화자를 물려받지 않습니다.
- `viewer/scenario-cpk-locations.json`은 원본 STG CPK의 `IDxxxxx` 파일에서
  `pid_MUZIN` 지역 블록을 직접 추출한 경계 목록입니다. 뷰어는 번역문이
  지역 표시처럼 보이는지만 추측하지 않고, 시나리오 키와 일본어 원문을 이 목록과
  대조해 지역 행을 분리합니다. 목록에 없는 DLC·새 파일은 양쪽 물결표 형태를
  보조 규칙으로 사용합니다.
- 화자 묶음은 엑셀 행의 이름 추정만 사용하지 않고 `scenario-speakers.json`의
  CPK `SP/SB/SF/SG` 슬롯과 내부 `internalId` 경계를 함께 사용합니다. 원본
  `STG0001a.cpk`의 `ID00003@FILE-ID00004` 화자 블록이 끝나고 `ID00007`
  나레이션 멤버가 시작되면 이전 화자를 이어받지 않습니다.
- `최대 N/N칸 · 한계`는 기존 번역에서 산출한 한 줄 최대치와 정확히 같은 경우입니다.
  초과가 아니라도 실제 대사창의 경계에 닿은 행이므로 번역을 줄일지 사람 검수로
  결정할 수 있습니다.
- 화면 시작·끝의 `「 」`는 원본 행에 없을 때 뷰어가 표시용으로 보완한 문자이며,
  글자 수 판정에서는 제외합니다. 따라서 `26/26칸`은 실제 번역 내용이 26칸이라는 뜻입니다.
- `$n`, `$l`, `$F`, `$c` 및 `&n`, `&l`과 같은 제어문자는 원본 토큰을 보존한 채 각각 `히비키`,
  `카미시로`, `히비키 카미시로`, `Z-BLUE`로 표시하고 이름·부대 색을 따로
  적용합니다. 툴팁에는 실제 토큰을 남겨 패치 검수 시 원문과 대조할 수 있습니다.
- 용어사전 표기인 `《대시공진동》`은 대사창에서 `대시공진동` 본문만 분홍색으로
  표시합니다. `《`·`》`는 화면에 표시하지 않으며, 본문 글자만 칸과 줄 용량에 반영합니다.
- 한 줄 한도를 넘는 행은 먼저 같은 대사의 다음 화면 줄로 자동 넘깁니다. 이렇게
  나눈 결과가 3줄을 초과할 때만 전체 문장을 기존 한 줄 최대치 안에서 비슷한
  길이로 재배치합니다. 세 줄 총 용량도 넘으면 마지막에 `…`를 붙여 화면 안으로
  축약하고 `3줄 균등 배치 · 미리보기 축약` 배지를 표시합니다. 이 처리는 뷰어
  표시 전용이며 JSON·CPK의 물리 행을 바꾸지 않습니다. 실제 JSON을 수정할 때는
  이 배지를 참고해 문장을 직접 다듬고, 고유명사·제어문자는 삭제하지 마세요.
- `viewer/scenario-titles.json`은 게임 원본 CPK의 `STG*/ID00002` 주석에서
  추출한 화수·일본어 제목과 직접 번역한 `titleKo` 목록입니다. 목록과 화면 상단에는
  `제N화 · 한국어 제목 · STG키`를 표시하며, 원문 제목은 JSON의 `titleJa`에서
  함께 확인할 수 있습니다. CPK·롬 자체는 저장소에 포함하지 않습니다.
- **신규 번역 수정**에서 화자명은 건드리지 않고 대사만 직접 고칠 수 있습니다. **검사 후
  신규 번역 저장**을 누르면 `newTranslation`을 갱신하고 제어문자 종류·순서·개수,
  `《》` 용어 괄호, 최대 3줄, 기존 번역 기준 글자 수, 일본어 잔존 여부를 검사한 뒤
  JSON을 저장합니다. 오류가
  있어도 파일은 저장되지만 검사 결과에 오류를 표시하므로 실제 패치 전 반드시
  수정하세요. Chromium 계열의 로컬 서버에서는 저장 위치를 선택할 수 있고, 그 외
